### Week 3 Objectives:

* Deploy trial Healthcare Web applications onto AWS Cloud infrastructure utilizing a combination of **Amazon EC2** for compute servers and **Amazon S3** for object storage (avatars, PDF/JSON AI RAG conversation history reports, static assets).
* Complete the cloud configuration of **Amazon Cognito** to handle authentication (Authentication) and role-based authorization (Role-based: Admin, Doctor, Patient) using `cognito:groups`.
* Integrate the **Amazon S3** service into the Backend (NestJS) using AWS SDK v3, leveraging **IAM Roles attached to EC2** and **Presigned URLs** for secure file uploads and retrievals.
* Configure an **Nginx Reverse Proxy** on EC2 to route requests (Routing), set up SSL/TLS, and apply Rate Limiting to protect the Backend API system.
* Test connections and prepare the file storage flow for **Pre-consultation Reports** generated by the AI RAG Medical Consultation Chatbot onto S3.

### Week 3 Achievements:

* Successfully launched and configured the **Amazon EC2** server, smoothly setting up security ports using Security Groups.
* Packaged and deployed the Healthcare Web application (Next.js & NestJS), running stably on the EC2 server environment via Docker Containers.
* Fully configured **Amazon Cognito** on the Cloud supporting standardized RBAC authorization aligned with Business Flows (assigning `Patient`, `Doctor`, `Admin` groups and extracting `cognito:groups` from JWT Tokens).
* Successfully integrated **Amazon S3** into the NestJS Backend system, enabling secure storage for doctor avatars, attachments, and medical consultation history files (Pre-consultation Reports).
* Applied **IAM Roles to the EC2 Instance** for secure interaction with S3 without hardcoding access keys (Access Keys) inside `.env` configuration files.
* Tested seamless connectivity for generating and retrieving AI Chatbot **Pre-consultation Report** files via S3 Presigned URLs.
* Configured Nginx Reverse Proxy to control and route incoming data streams while enhancing security for the API system.
* Prepared compute and static storage infrastructure ready for integrating the AWS RDS Cloud Database in Week 4.
